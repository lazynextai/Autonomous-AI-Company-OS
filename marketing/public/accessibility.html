Our commitment

Lazynext is an accessibility company: our product is a WCAG scanner. We hold this website to the same standard we sell, and we would rather state our gaps plainly than publish a claim we have not earned.

We want everyone to be able to read this site and use it, including people who navigate by keyboard, use a screen reader, magnify the screen, dictate instead of type, or turn off animation. Accessibility is treated as a defect class here, not a feature request.

Conformance target

This site aims to conform to WCAG 2.1 Level AA, and we are committed to reaching it; we do not claim verified conformance.

WCAG 2.1 is the standard referenced by the European Accessibility Act, the US Section 508 refresh, and most public-sector procurement questionnaires. We have not yet completed an independent third-party audit, so any statement that this site "conforms" today would overstate what we know. What we can document is below: the target, the measures in place, and the specific shortcomings we have found ourselves.

Assessment approach: self-evaluation. Each page is checked automatically on a daily schedule by our own Accessibility Checker (which tests 74 WCAG criteria plus a rendered keyboard and focus trace, not only static markup), and new page patterns are reviewed manually before they ship. Where an automated check and a human judgement disagree, the human judgement is recorded in the limitations section below.

Scope

This statement covers the marketing site served from lazynext.com, including www.lazynext.com and marketing.lazynext.com, and the pages listed in the sitemap.

It does not cover separate properties we link to: the dashboard at dashboard.lazynext.com, the product at checker.lazynext.com, the design system at penpot.lazynext.com, our GitHub organisation, or transactional email. Those are maintained separately and each needs its own statement.

Technologies relied upon: HTML, CSS, and — on a few pages only — JavaScript for progressive enhancement. This page uses no JavaScript at all. The site publishes no audio or video content, so captions and audio description do not currently apply.

Measures taken

  • Semantic structure. HTML5 landmarks (header, nav, main, footer), one h1 per page, headings in logical order, and a real lang attribute on every page.
  • Keyboard access. Everything can be reached and operated without a pointer, a visible skip link is the first focusable element, and focus is drawn with a 3px outline that is never removed without replacement.
  • Contrast. Body text, links and interface text are set above the 4.5:1 minimum for normal text; decorative colour is never the only way information is conveyed.
  • Reflow and zoom. The layout is responsive down to 320px, text can be resized to 200% without loss, and wide tables scroll inside their own container rather than forcing the page sideways.
  • No motion or distraction. No autoplaying media, no carousels, no animation on this site, and no time limits on any page.
  • Plain language. Page titles, link text and form labels describe their destination or purpose; navigation is consistent across pages.
  • Continuous checking. The site is rescanned daily by our own monitoring, and issues it reports are triaged like any other bug — this statement is reviewed at the same time.

Known limitations

These are the gaps we know about as of 5 November 2026. They are listed rather than hidden, and each has an owner.

  • The status page depends on JavaScript. lazynext.com/status builds its service list and uptime display client-side. With JavaScript disabled the rows stay at "checking…" and no change history appears. The rest of the site's content does not depend on scripting.
  • The waitlist form has no non-JavaScript fallback and no live region. On the home page, submitting the form sends a request with JavaScript and writes the result as plain text; that message is not announced to screen reader users, and there is no fallback when scripting is off. If the form does not work for you, email support@lazynext.com and we will add you to the list by hand.
  • Data tables and code samples can require horizontal scrolling. On the documentation page, wide tables and long code lines scroll inside their container. This is deliberate for tabular data, but it means some content is not fully readable at 400% zoom on a narrow viewport.
  • Email and linked third-party services are outside our control. We send transactional mail through Brevo and link to GitHub and Penpot; we cannot guarantee the accessibility of interfaces we do not build.
  • Some content is still being audited. Older pages have not all been through a manual review. Pages reviewed so far: this statement, home, docs, legal, pricing, status. The changelog is pending.

Report an accessibility issue

If any part of this site blocks you, we want to know — including if something here is simply harder to use than it should be. Email:

support@lazynext.com — please put "Accessibility barrier" in the subject line.

Helpful, but optional: the page address, what you were trying to do, what happened instead, and the browser and assistive technology you were using. You do not need an account, and you do not need to explain your disability.

How we respond

  1. We acknowledge every report within two business days.
  2. We tell you what we intend to do within ten business days, or ask a clarifying question if the issue is not reproducible.
  3. If a fix will take longer, we say so honestly and, where we can, offer another way to get the same information or complete the same task in the meantime.
  4. When the fix ships, we reply on the same thread and update this statement if a listed limitation has changed.

Reports are read by a person, not only by a scanner. This page is the record of what we found ourselves; your report is how the list gets more honest.
