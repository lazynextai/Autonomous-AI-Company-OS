## 5. Reply-handling plan for round one (and round two) replies

Campaign sends carry `Reply-To: support@reply.lazynext.com` because `config:inbound_addr` is set. A
reply therefore lands as a **new `support_tickets` row** (Brevo inbound parse → webhook →
`POST /api/v1/brevo/inbound/<secret>`), gets one automatic acknowledgement carrying `[#id]`, and
every later reply in that thread appends to the same ticket with no further auto-ack. Mail sent
straight to `support@lazynext.com` instead does **not** create a ticket — read it in Gmail and reply
from `support@lazynext.com`; log the substance in `crm_leads.notes`.

**Rules that apply to every class below**

1. One business day maximum to reply. Log every exchange against the CRM row before answering.
2. Never reply from a personal mailbox; the sender of record is `support@lazynext.com`.
3. Never offer anything outside the approved copy: no custom discounts beyond `WELCOME20`, no
   "we'll do the audit for free", no VPAT/ADA-certification language, no effort estimates.
4. One follow-up maximum. A second unanswered touch is the founder's call, not an operator's.
5. Never paste a prospect's address or contents into a public doc; the CRM row is the record.

### 5.1 "Yes — send me my score / here is my URL"

What the reply needs:

1. Run the real scan on the URL they gave (`POST /scan {"url": ...}`; add `"site":true` if they
   named a whole site rather than one page — the free tier crawls 3 pages, Pro 10).
2. Answer with: **score**, **how many checks failing** (grouped: contrast / keyboard-focus / forms /
   ARIA / headings), **the top 5 fixes in priority order**, and the report link.
3. Do **not** require signup and do not attach a PDF. The report URL is enough; exports
   (`/report/<id>.csv|.json|.pdf`) exist if they ask for a machine-readable or printable copy.
4. Close with one sentence: monitoring/CI exist if they want the checks on every deploy, 30-day trial,
   `WELCOME20`. No pressure language.
5. Set the CRM row: append ` | replied:<date> score:<n>` to `notes`, and promote `status` to
   `engaged` (a reply is a stronger signal than the automatic click promotion).

### 5.2 "Not interested" / "we already have a vendor"

1. Reply with **one or two sentences**: thanks, no further outreach from us.
2. Write `crm_leads.status='disqualified'` with ` | declined-outreach:<date>` on `notes`.
3. Set `email_contacts.subscribed=0` for that address so the next campaign segment skips it.
4. Do **not** write a KV `unsub:` key for this. `unsub:` is the hard-suppression flag (it also
   represents bounces/complaints and gates sequence + reminder mail); a polite decline is honoured by
   the CRM + contact flags, and keeping the distinction preserves the real suppression count.
5. If they say "not now, revisit in Q2", use `status='nurture'` with
   ` | revisit:<YYYY-MM-DD>` instead — that is the bucket the founder-perspective draft (id 10) is
   waiting for.

### 5.3 "Unsubscribe" / "stop emailing" / "remove me"

This is a **legal** instruction, not a preference. Execute it the same day:

1. `POST {CLOUDFLARE_API_URL}/unsubscribe` with the internal bearer and body `{"email": "<addr>"}` —
   **no `/api/v1` prefix**; that layer wants `lzk_` keys and returns a misleading 401.
2. That single call is `unsubscribeEmail()`: KV `unsub:<email>` (1-year TTL), D1
   `email_contacts.subscribed=0`, and the Brevo blacklist. Idempotent — safe to re-run.
3. Do not send a marketing reply. At most a one-line confirmation ("removed, sorry for the
   interruption") — and **no footer**, since a footer on a confirmation re-opts nothing and reads as
   another marketing message.
4. Verify: `GET /kv/get?key=unsub:<email>` returns `{"value":"1"}` and the contact row reads
   `subscribed=0`. If the KV write is missing, the suppression did not land — escalate, do not
   assume.
5. Never argue, never ask why, never offer an incentive to stay.

### 5.4 Spam complaint / hard bounce / "who gave you my address?"

- **Hard bounce or Brevo spam complaint**: Brevo's webhook already routes these through the same
  `unsubscribeEmail()` suppression path. Confirm the `unsub:` key exists; if the complaining address
  is still subscribed, run §5.3 step 1 manually.
- **"Where did you get my address?"**: answer factually — publicly published business contact on
  their own company site, found via search, and it was one outreach note, not a newsletter. Point at
  the unsubscribe link. Do not cite a person, a purchased list, or a partner.
- A complaint is a signal to **stop the remaining sends to that domain**, not just that address.

### 5.5 What never happens without the founder

Rebooking a held-out address (`careers@usablenet.com`, `press@siteimprove.com`), re-mailing an
address that declined, sending a third touch, adding addresses to the list, or changing the segment
override. Round two's send is itself a founder action.
